# Отчёт по авансам и остаткам по договорам

Считает по каждой работе: цену, сколько выплачено, сколько осталось оплатить;
и итоги по каждому договору — на заданную дату (по умолчанию на сегодня).

Python 3.10+, только стандартная библиотека, ставить ничего не нужно.
Деньги — `Decimal`, до копейки, без float.

## Запуск

Из папки проекта (там же, где `advance_report.py` и `data/`):

```
py -3 advance_report.py --data data --date 2026-11-10 --out-file report_2026-11-10.txt
```

Отчёт печатается в консоль и дополнительно пишется в `report_2026-11-10.txt` в UTF-8
(на Windows консоль иногда ломает кириллицу — файл читается нормально).

Варианты формата:

```
py -3 advance_report.py --data data --date 2026-11-10                    # только консоль
py -3 advance_report.py --data data --date 2026-11-10 --format csv --out out
py -3 advance_report.py --data data --date 2026-11-10 --format json
py -3 advance_report.py --data data --date 2026-11-10 --format all --out out
```

`--format csv` кладёт в `out/` два файла с разделителем `;`: `report_works.csv`
(строка = работа) и `report_contracts.csv` (строка = договор). Оба открываются в Excel
без плясок с кодировкой (UTF-8 с BOM).

### Параметры

| Параметр | Что делает |
|---|---|
| `--data` | папка с `contracts.csv`, `works.csv`, `payments.csv` (по умолчанию `data`) |
| `--date` | дата отчёта `ГГГГ-ММ-ДД` (по умолчанию сегодняшняя) |
| `--format` | `text` (по умолчанию), `csv`, `json`, `all` |
| `--out` | папка для CSV (по умолчанию `out`) |
| `--out-file` | куда дополнительно записать текстовый отчёт |
| `--allocation` | `accepted-first` (по умолчанию) или `spread` — как разносить платежи без привязки к работе |
| `--strict` | вернуть код 1, если есть предупреждения по данным |

Коды возврата: `0` — всё сошлось, `1` — есть вопросы к данным (они перечислены в блоке
«ЧТО ТРЕБУЕТ ВНИМАНИЯ»), `2` — не удалось прочитать файлы.

## Чем это сделано

Задание предлагало Claude Code, но работа шла в другом агенте (OpenClaw) — поэтому вместо
`/export` из Claude Code приложена автоматическая выгрузка истории сессии,
`TRANSCRIPT.md`: все сообщения, вызовы инструментов и их вывод, без правок (только длинные
выводы обрезаны до 4 000 символов). Язык реализации — Python, как просили.

## Тесты

```
py -3 -m unittest discover -s tests -v
```

17 тестов: числа по исходным данным, отменённая работа, возвращённый платёж, платёж
в очереди, платёж, привязанный к работе, работа, принятая после даты отчёта, чувствительность
к дате, оба режима распределения, точность до копейки.

## Как считается

1. **Оплачено** — платежи договора, у которых деньги ушли не позже даты отчёта
   и к этой дате не вернулись подрядчику. Платёж со статусом `queued` в «оплачено»
   не входит: показывается отдельной строкой «в очереди».
2. **Платёж с привязкой к работе** идёт прямо на эту работу — но не больше её цены.
   Излишек уходит в общий аванс договора с предупреждением.
3. **Платёж без привязки** — общий аванс договора. Он закрывает работы в порядке
   «сначала принятые на дату (по дате приёмки), затем ещё не принятые (по номеру)».
   Так по каждой работе видно, за что уже рассчитались, а остаток аванса оседает
   на будущих работах. Режим `--allocation spread` разносит тот же аванс
   пропорционально ценам работ.
4. **Осталось оплатить в договоре** = цена действующих на дату работ − оплачено.
   Отдельной строкой: сколько из этого остатка приходится на уже принятые работы
   (это долг), и сколько — на ещё не принятые.
5. **Отменённые работы** к оплате не подлежат и в цену работ не входят. Если по
   отменённой работе всё-таки были деньги — попадают в отдельную строку и в блок
   «ЧТО ТРЕБУЕТ ВНИМАНИЯ».
6. **Свободный аванс** — деньги, которым не нашлось работы (оплачено больше, чем стоят
   работы). Показывается отдельно и в блоке внимания.
